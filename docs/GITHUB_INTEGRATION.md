# Reactively GitHub Integration

## Goal

GitHub integration should give users ownership, backup, collaboration, and export of their generated React Native project without forcing Reactively to reverse-engineer arbitrary external code changes.

## Beta Ownership Model

Reactively is the source of truth for generated code.

```text
Reactively Project
      ↓
Generator
      ↓
Git Repository
```

Do not promise full bidirectional visual round-trip from arbitrary code edits.

## Repository Layout

Recommended exported repository:

```text
README.md
reactively.json
app/
src/
├── generated/
├── custom/
└── runtime/
assets/
package.json
```

Generated files should contain a short ownership header where appropriate.

## Git Operations

Initial supported actions:

```text
Connect GitHub
Create repository
Connect existing empty repository
Commit generated changes
Push
Pull
View changed files
Open repository
Disconnect
```

Pull behavior must be conservative.

## Pull Rules

### Generated Files

If external changes are detected in Reactively-owned generated files:

- do not import them into the visual document
- warn that regeneration may overwrite them
- offer to preserve/export a branch or copy

### Custom Files

User-owned `src/custom` files may be pulled and preserved normally.

## Branching

Beta can default to a single configured branch.

Later support:

```text
branch selection
preview branches
publish from branch
```

## Commit Strategy

Generated output should be deterministic so normal visual edits create understandable Git diffs.

Possible default commit messages:

```text
Update Home screen
Update app generated by Reactively
Publish version 1.2.0
```

Allow custom messages.

## Credentials

Use GitHub OAuth or GitHub App-based authorization.

Never store raw GitHub passwords.

Store refresh/access credentials using secure OS or backend credential storage.

## Reactively Metadata

Include a small repository metadata file:

```json
{
  "projectId": "...",
  "runtimeVersion": "1.0.0",
  "schemaVersion": 1
}
```

Do not embed user secrets.
